Experience

Independent AI Developer

2025 – Present

I design, build, and operate LLM applications end to end, across my own products and community collaborations, with cloud-hosted services in daily use. Most examples below come from the Narrative Memory Engine.

  • Judgment and generation on separate models. Closed questions go to a fast decision model that returns a probability; only prose goes to a generative model. The decisions run in parallel with retrieval, so narration starts about 350 ms after a request arrives and a full turn takes about 3 s.
  • State held by the application, not the conversation. Anything that must stay true lives in engine state, and the prompt is rebuilt from it each turn. Text the user has not unlocked is never sent to the model, so a leak is ruled out by construction instead of by instruction.
  • Thresholds chosen from data, changes checked by replay. Each decision has its own threshold, set from measured separation on a labelled test set. A change ships only if replayed games improve. The analysis tooling is open source as s1scope.
  • An expert-review workflow in daily institutional use. Sole developer of a patented system that combines image processing, LLM classification, and structured data population, replacing manual inspection and form filling spread across several tools.
  • Agents and model selection in other services. Built document and workflow automation with tool orchestration, MCP integrations, structured outputs, and failure handling. Chose and routed models by comparing quality, latency, reliability, and cost in real workflows.

Independent Work

Decision-model evaluation · Open source · MIT

s1scope

A decision model answers with a probability, so every question needs a threshold and someone has to know what that threshold costs. s1scope reads calls already logged and shows, per question, the distribution, the calibration, and the error counts at any threshold, then compares two runs sample by sample.

Built to tune the Narrative Memory Engine. Local and read-only, so logged prompts never leave the machine.

LLM game engine · Interactive prototype

Narrative Memory Engine

A mystery game in which a model narrates but cannot leak the plot or lose track of the world. Undiscovered clue text is never in the prompt, world state lives in the engine, and a decision model settles what happens before the narrator writes.

Narration starts about 350 ms after the request, with changes checked by replaying recorded games.

LLM-assisted retrieval & ranking · Closed-source proof of concept

Job Posting Ranker

Ranks current job postings against one candidate profile. Deterministic eligibility rules run before any model call, the model scores four fit dimensions that are combined with fixed weights, and fetching, filtering, and ranking are separate, inspectable steps.

Each company's fetch is checkpointed, so a failed source never discards a good snapshot. Rankings are reused unless re-ranking is requested.
